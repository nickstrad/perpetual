# V1.1 architecture

The host is the computer running `perpetual`, the command-line tool.
A virtual machine runs its own operating system inside the host.
Firecracker manages that machine; the guest means everything running inside it.
`vmagent` accepts tasks; `fx` uses an AI model to edit code.
SQLite stores tasks and results in one database file.
A snapshot saves guest memory, disk, and machine state for later restoration.

```text
+----------------------------------------------------------------------------+
| HOST                                                                      |
|                                                                            |
| You --> perpetual                                                          |
|             |                                                              |
|             +-- machine commands --> Firecracker (keeps running)            |
|             |                        |                                     |
|             |                        | manages                             |
|             |                        v                                     |
|             |     +----------------------------------------------------+   |
|             |     | GUEST: one virtual machine                          |   |
|             |     |                                                    |   |
|             +---->| vmagent                                            |   |
| tasks, results,   |   |                                                |   |
| logs, settings    |   +----> SQLite: task queue and results             |   |
| over a virtual    |   |                                                |   |
| network link      |   +----> runner: one task per run command           |   |
|                   |           |                                        |   |
| .env key -------->| memory    +----> fx ----> /workspace: code files    |   |
| after each start  |           |       |                                |   |
|                   |           |       +-- model requests -----------+  |   |
|                   |           +----> logs and task outcome           |  |   |
|                   |                                                |  |   |
|                   | Guest disk: code, database, logs, fx sessions    |  |   |
|                   +------------------------------------------------|--+   |
|                                                                    |      |
| Reusable image -- copy --> working guest disk                       |      |
| Saved snapshot ----------> restore guest memory and disk            |      |
| .state/vm.json ----------> remembers the running machine             |      |
|                                                                    |      |
| Host internet connection <-----------------------------------------+      |
+-----------------|----------------------------------------------------------+
                  v
         Vercel AI Gateway --> AI model
```

Machine commands use a local connection directly to Firecracker.
Each invocation exits; the guest continues running tasks.

Saving refuses active runs, attempts key erasure, freezes, copies, then stops the guest.
Restoring loads saved state and sends the key again.

## Biggest risks

- Key erasure may leave memory copies, making snapshots sensitive.
  The runner example enables trace logs despite instructions forbidding them by default.
  Those logs could expose secrets on disk.
- The host tool requires administrator access; v1 defers additional security restrictions.
  The guest accepts requests without checking callers' identities.
  Keep its network link private.
- The plan leaves `fx` response parsing unverified.
  Incorrect parsing could label unfinished work as completed.

## Pros

- The guest boundary separates agent execution from the host operating system.
- Image copies give fresh starts a consistent environment.
- Snapshots preserve code and task history together.

## Cons

- One guest runs one task at a time, limiting throughput.
- Saving interrupts availability; restoration depends on matching machine settings and Firecracker versions.
- Fresh starts replace the working disk; save valuable work before restarting.
